## 0. 定位与边界

**一句话定义**：按一个键，把剪贴板里的东西翻译或查词，看完即走。

**主场景语言对：中 ↔ 英**。查词和 prompt 优先针对这一对调优，其他语言走通用路径（能用但不专门优化）。

**产品原则**（冲突时按顺序取舍）：

1. 快 > 全。首屏出现速度优先于结果完整度。
2. 零决策。用户不需要选引擎、不需要选语言方向、不需要理解 API。
3. 不留痕。不进任务栏、不留窗口、不存历史。

**v1 明确不做**：OCR、插件系统、主题、划词自动弹出（需辅助功能权限）、历史持久化、账号体系、自建中转、多目标语言。

**成功标准**：你自己连续用两周没有换回浏览器翻译。达不到就不开源。

## 1. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | Tauri v2 | 包体小；Windows 复用系统 WebView2；将来加 macOS 不重写 |
| 前端 | React + TypeScript | 你的主力栈，UI 面积小，不需要状态管理库 |
| 后端 | Rust | 热键、剪贴板、窗口样式、HTTP 全在 Rust 侧 |
| 首发平台 | Windows | 你的主力系统，能 dogfood |
| 二期平台 | macOS | 开源后再做，届时补 Apple 翻译框架作为免 key 降级 |

**Rust 侧职责边界**：全局热键注册、剪贴板事件监听、窗口样式（NOACTIVATE）、Provider 实现与流式转发、凭据存取。前端只负责渲染和设置界面，不碰网络。

**关键依赖**：`tauri-plugin-global-shortcut`、`tauri-plugin-clipboard-manager`、`tauri-plugin-single-instance`、`tauri-plugin-opener`、`windows` crate（窗口样式 `WS_EX_NOACTIVATE` / `WS_EX_TOOLWINDOW`）、`reqwest`（SSE 流式）、`keyring`（凭据）。

> **不使用低级键盘钩子**。默认热键为普通组合键，`tauri-plugin-global-shortcut` 已完全够用。这同时规避了键盘钩子被杀软误判为键盘记录器的风险 —— 对一个未签名的开源工具，这个风险不值得承担。「双击 Ctrl」等修饰键连击方案归入 §11 推迟清单。

## 2. 交互设计

### 2.1 触发方式

- **主入口**：全局热键 **`Ctrl+Alt+D`**（默认，可改）。读取当前剪贴板 → 弹窗 → 出结果。
- **副入口**：托盘图标点击，打开一个带输入框的窗口（手动粘贴场景）。
- **v1 不做**：复制后自动弹出（已决策，见 §7 Q2）。

#### 热键规则（冻结）

1. 用 `tauri-plugin-global-shortcut` 注册，底层走 `RegisterHotKey`，不安装任何键盘钩子。
2. **默认 `Ctrl+Alt+D`**。选它的理由：左手单手可达；D 对应 dictionary 好记；Windows 上冲突面小（仅放大镜运行时会占用 `Ctrl+Alt+D` 切换停靠模式，属罕见场景）。
3. **已排除的候选**：`Ctrl+Shift+D`（VS Code 打开调试面板）、`Ctrl+Shift+Space`（VS Code 参数提示）—— 对开发者天天冲突。
4. **注册失败必须显式提示**。`RegisterHotKey` 在热键已被其他进程占用时会失败，此时启动即弹提示并引导用户改键，不得静默失败。
5. 热键可在设置中修改，改后立即生效，无需重启。
6. **再次按下热键 = toggle**：窗口可见时按下则关闭（Loading 中除外，见 §4.3）。

### 2.2 窗口状态机

```
        热键 / 托盘
Hidden ─────────────> Showing ──> Loading ──> Result
  ^                                  │           │
  │                                  v           │
  └──── Esc / 失焦 / 5s 无操作 ──── Error <──────┘
```

**状态定义**：

| 状态 | 说明 |
|---|---|
| Hidden | 窗口已创建但 `hide()`，不销毁 |
| Showing | 窗口出现在光标附近，显示原文 + 骨架屏 |
| Loading | 请求进行中，可被新的热键触发打断（取消旧请求） |
| Result | 结果渲染完成 |
| Error | 网络失败 / key 无效 / 限流，显示可操作的错误文案 |

**关闭条件**：Esc 键、点击窗口外、热键再次按下（toggle）。
**不关闭的情况**：窗口内有文本选中时的失焦（用户可能在复制译文）。

### 2.3 延迟预算（硬指标）

| 阶段 | 目标 | 实现要点 |
|---|---|---|
| 热键 → 窗口可见 | < 50ms | 窗口启动时预创建并 hide，触发时只做 show + 定位 |
| 剪贴板读取 | < 5ms | Rust 侧同步读，不经前端 |
| 窗口 → 首字符 | < 800ms | 流式输出；Flash-Lite 模型；prompt 尽量短 |

**铁律**：窗口必须先出现再等结果，绝不能等结果出来再弹窗。骨架屏比延迟弹窗的体感好一个数量级。

### 2.4 窗口行为（Windows 特有）

- `WS_EX_NOACTIVATE`：弹窗不抢焦点，用户原来的输入光标不丢。
- `WS_EX_TOOLWINDOW`：不出现在 Alt+Tab 和任务栏。
- 定位：光标位置右下偏移 12px，超出屏幕边界时翻转到另一侧。多显示器按光标所在屏计算。

## 3. 核心逻辑：查词 vs 翻译分流

> 这是整个工具最能拉开差距的地方，现有竞品普遍做得很糙。

### 3.0 语言方向判定（互译的关键）

设置项不是「目标语言」，而是**语言对**：母语 + 外语（默认 中文 + English）。

```
检测源语言 →
  源 == 母语        → 译成外语
  源 == 外语        → 译成母语
  源 == 其他语言     → 译成母语
```

这样「复制中文按热键出英文、复制英文按热键出中文」自然成立，用户永远不需要手动切方向。

**检测方式**：Rust 侧做粗判即可，不需要引入语言检测库——按 Unicode 区间统计 CJK 字符占比，> 30% 判为中文，否则判为英文/其他。剩余的模糊情况（中英混排的技术文档）统一按「非母语」处理，译成中文，符合直觉。

**UI**：结果窗口顶部显示 `中 → EN` 这样的小标签，可点击手动翻转。判断错了一键改，不做设置项。

### 3.1 分流规则

输入先 trim，然后按顺序判断：

```
1. 含换行符 或 长度 > 80 字符          → 翻译
2. 含句末标点（. ! ? 。！？）            → 翻译
3. 英文：无空格 且 ≤ 24 字符            → 查词
4. 英文：≤ 3 个词 且 ≤ 30 字符          → 查词（短语模式）
5. 中文：≤ 6 字符 且 无标点             → 查词
6. 其他                                → 翻译
```

**规则 4 对英文特别重要**。英语查词的高频需求有一大半是短语而非单词：动词短语（`take off`、`look into`）、固定搭配（`in terms of`）、俚语（`piece of cake`）。这些逐词翻译全是错的，必须走查词路径拿到整体释义。日语场景下这条规则几乎用不上，但中英互译里它的价值不亚于规则 3。

**规则 5 的 6 字符**：覆盖绝大多数中文词和四字成语。再长基本就是短句了。

**兜底**：结果窗口右上角提供「切换模式」小按钮，分流判断错了用户一键改。规则不追求 100% 准确，追求 90% + 一键纠正。

### 3.2 两套输出格式

**查词** — 结构化 JSON，非流式（等完整再渲染）：

```json
{
  "word": "原词",
  "reading": "英文→IPA 音标；中文→拼音；其他语言→null",
  "lemma": "词形还原后的原形，无变化时为 null",
  "senses": [
    { "pos": "词性", "def": "释义", "note": "语感/使用场景/正式度，可选" }
  ],
  "collocations": ["常见搭配，2-4 条，可为空数组"],
  "examples": [
    { "src": "例句原文", "dst": "例句译文" }
  ]
}
```

**`collocations` 是为中英场景专门加的**。中文母语者查英文词，痛点往往不是"这个词什么意思"，而是"这个词该怎么搭"——`make a decision` 还是 `do a decision`。这个字段的实用价值高于多给一条例句。反向（中→英）时它给的是该中文词对应的常见英文表达。

**`lemma` 在英文场景比日语更常用**：不规则动词（`went`→`go`）、比较级（`better`→`good`）、复数变形（`crises`→`crisis`）。中文没有形变，这个字段恒为 null。

**翻译** — 纯文本流式：

- 主体：译文，逐字输出
- 尾部（可选，仅当原文含变形词或特殊表达时）：一行简短说明

### 3.3 为什么查词不流式

查词的 UI 是分区块的（读音区 / 释义区 / 例句区）。流式 JSON 会导致区块逐个闪现、布局跳动，体感比等 600ms 一次性出现更差。翻译是单块连续文本，流式收益明确。

**这条是有意的不一致，不要在实现时"统一"掉。**

### 3.4 Prompt 设计要点

- 查词 prompt 强制 JSON schema 输出，明确禁止 markdown 代码块包裹。
- 释义按**实际使用频率**排序，最多 4 个义项。查词是为了快速确认，不是背词典。
- **英→中显式要求标注熟词僻义**。中文用户查一个"认识"的英文词，多半正是因为它在上下文里不是常见义（`address` 作"处理"、`subject` 作"使遭受"）。prompt 里要求：如果该词有明显区别于最常见义的用法，必须列出。这一条对中英场景的价值最高。
- 英文查词必须给 IPA 音标；中文查词给拼音（带声调）。
- 中→英时，`senses` 给的是不同语境下的英文对应词，并标注语域差异（书面/口语/正式）。中文用户最常见的错误是选了语域不对的词。
- 翻译 prompt 强调：只输出译文，不加"译文："前缀、不加引号、不解释。
- 中→英翻译额外要求：不要逐字直译，输出地道英文表达。这是中文母语者用翻译工具的主要不满来源。

### 3.5 「换个说法」按钮

仅出现在**翻译结果**下方，查词结果不显示。

**行为**：点击后用同一原文重新请求，prompt 追加「换一种表达方式，与前一版明显不同」，流式覆盖原结果。

**约束**：

- **替换，不累积**。v1 不保留历史版本、不做并排对比、不做「上一版」按钮 —— 这三样都归入 §11 推迟清单。
- 复用 `start_request`，不新增 IPC 命令。入参增加 `rephrase: bool` 与 `previous: Option<String>`。
- 请求期间按钮置灰，防止连点产生并发请求。
- 不限次数。每次点击都是一次完整请求，同样受 §4.2 的限流与错误处理约束。

**设计意图**：把成本留给主动需要的人。默认路径（复制 → 热键 → 看结果 → 关闭）不因此变慢一毫秒。这是「快 > 全」原则的一次具体应用 —— 实现时不要为了「更有用」把第二版做成默认输出。

## 4. Provider 抽象

```rust
trait Provider {
    fn capabilities(&self) -> Capabilities;
    async fn translate(&self, req: TranslateReq) -> Result<TextStream>;
    async fn lookup(&self, req: LookupReq) -> Result<Definition>;
}

struct Capabilities {
    supports_lookup: bool,   // 传统翻译 API 为 false
    supports_stream: bool,
}
```

**v1 实现**：

| Provider | 用途 | lookup |
|---|---|---|
| `GeminiProvider` | 默认，free tier | ✅ |
| `OpenAICompatProvider` | 覆盖自建 / 第三方 / Ollama | ✅ |

**降级规则**：`supports_lookup == false` 时，查词请求自动走翻译路径，UI 不显示词典区块。这条现在就要写进去，否则二期接 Apple 翻译框架要返工。

**前端完全不知道背后是谁**。前端只发 `{ text, mode }`，收 `{ type: "definition" | "text", ... }`。

### 4.1 IPC 契约（冻结，实现不得改名）

**Commands（前端 → Rust）**

| 名称 | 入参 | 返回 |
|---|---|---|
| `start_request` | `{ text, mode, direction }` | `request_id: String` |
| `cancel_request` | `{ request_id }` | `()` |
| `read_clipboard_text` | — | `Option<String>` |
| `load_settings` / `save_settings` | — / `Settings` | `Settings` / `()` |
| `validate_api_key` | `{ provider, key, model }` | `Result<(), ErrorKind>` |
| `hide_panel` | — | `()` |

**Events（Rust → 前端）**

| 事件 | payload |
|---|---|
| `req:chunk` | `{ request_id, delta }` |
| `req:definition` | `{ request_id, definition }` |
| `req:done` | `{ request_id }` |
| `req:error` | `{ request_id, kind, message }` |
| `panel:show` | `{ text, mode, direction }` |

**所有事件都带 `request_id`**。前端收到非当前 `request_id` 的事件一律丢弃——这是防止取消旧请求后内容串台的唯一手段，不能省。

### 4.2 错误分类（冻结）

| kind | 触发条件 | UI 表现 |
|---|---|---|
| `NoApiKey` | 未配置 | 「还没配置 API」+ 打开设置按钮 |
| `InvalidApiKey` | 401 / 403 | 「API Key 无效」+ 打开设置按钮 |
| `RateLimited` | 429 | 「请求太频繁」+ 倒计时后自动重试一次 |
| `Network` | 连接失败 | 「网络连接失败」+ 重试按钮 |
| `Timeout` | 15s 内无首字符 | 「响应超时」+ 重试按钮 |
| `EmptyClipboard` | 剪贴板无文本 | 「剪贴板里没有文本」 |
| `TooLong` | 超过 5000 字符 | 「内容过长（N 字符），请分段」 |
| `ParseError` | 查词 JSON 解析失败 | 降级为纯文本展示模型原始输出 |
| `Unknown` | 其他 | 显示原始错误信息 + 重试按钮 |

**禁止出现空白错误态或纯技术堆栈**。每个错误必须有一句人话 + 至少一个可点击的动作。

### 4.3 关键实现细节（这些不写清楚，执行时一定会被自行发挥）

**请求取消**：每个请求生成 UUID，Rust 侧持有 `AbortHandle`。发起新请求前无条件取消旧请求。

**Loading 中再次按热键**：不是关闭窗口，而是取消当前请求 + 重新读剪贴板 + 开始新请求。窗口保持可见。

**输入长度上限**：5000 字符。超过直接返回 `TooLong`，不截断后偷偷发送。

**查词 JSON 解析韧性**（模型必然会偶尔加围栏）：
1. 剥离 ` ```json ` / ` ``` ` 围栏
2. trim
3. 取第一个 `{` 到最后一个 `}` 的子串
4. 解析失败 → 返回 `ParseError`，降级展示原始文本，不抛异常不白屏

**剪贴板非文本**（图片、文件）：返回 `EmptyClipboard`，不尝试解析。

**窗口定位**：光标位置右下偏移 12px。右边界溢出 → 翻到光标左侧；下边界溢出 → 翻到光标上方。使用光标所在显示器的 work area（已排除任务栏），不是全屏尺寸。

**窗口尺寸**：固定宽 420px；高度自适应，区间 180–560px，超出部分滚动。

**单实例**：使用 `tauri-plugin-single-instance`，第二次启动时触发已有实例弹窗，不启动新进程。

**配置存储**：`%APPDATA%/<app>/settings.json`，**不含 API Key**。Key 单独存 Windows Credential Manager，service 名固定为 `<app>/provider/<provider_id>`。

**模型与端点**：写在配置里，不硬编码在业务逻辑。默认值为 Gemini 的轻量流式模型 —— 具体模型串在实现时查官方文档确认，本文档不写死（模型命名变动频繁）。

## 5. 设置界面

**硬上限：主区 3 项，其余折叠。**

| 位置 | 项 |
|---|---|
| 主区 | 全局热键 |
| 主区 | 语言对（母语 + 外语，默认 中文 + English） |
| 主区 | 开机启动 |
| 折叠区 | Provider + API Key + 模型名 |

**热键默认值**：待定，见 §7 Q1。

### 5.1 首次引导流程（关键路径）

**引导不是硬墙。** 用户可以选择「稍后配置」直接进入主界面 —— 托盘和热键照常工作，按热键弹出的窗口里显示配置引导卡片（含同样的按钮）。让用户先摸到真实的交互，配置动机反而更强；被拦在门口的用户很多会直接卸载。

```
1. 欢迎页，一句话说明工具做什么
2. 按钮：「获取免费 API Key」→ 浏览器打开 AI Studio 建 key 页
   同屏并列：「稍后配置」→ 直接进入主界面
3. 后台监听剪贴板，检测到 AIza 开头字符串 → 自动填入
4. 自动发一次测试请求验证 → 成功则进入主界面
5. 同屏明确告知：免费层的输入输出可能被 Google 用于改进产品
```

**目标：想配的人只需点两下、复制一次，不想配的人一步就能跳过。**

**第 2 步的深链兜底**（Google 改版 AI Studio 路径不是小概率事件，链接失效比没有链接更糟）：

- URL 写在配置文件里，**不硬编码在业务逻辑中**
- 按钮旁始终显示完整地址，可选中复制
- `opener` 调用失败时不静默，提示「请手动访问」并高亮该地址

**第 5 步的隐私告知不能省、不能折叠、不能弱化**。这个工具读的是剪贴板，用户可能刚复制过工作邮件。

**未配置状态下的行为**：按热键正常弹窗 → 显示 `NoApiKey` 引导卡片（见 §4.2），而非普通错误态。卡片内含「获取 API Key」和「打开设置」两个动作。

## 6. 数据与隐私

- API Key 存 Windows Credential Manager，不落明文配置文件。
- 历史仅存内存，最近 10 条，上下键翻阅，退出即失。
- 除 Provider 请求外不发起任何网络连接。无遥测、无崩溃上报（v1）。
- README 里明说：免费层数据会被 Google 用于训练，介意的用户请升级到付费层或改用其他 Provider。

**`Ctrl+Alt+D`**，走 `tauri-plugin-global-shortcut`，不用键盘钩子。规则见 §2.1。
> 决策过程：曾定为「双击 Ctrl」，因其需要低级键盘钩子（实现复杂 + 杀软误报风险）而改回组合键。修饰键连击方案推迟到 v2 作为可选项。

**Q2. ~~v1 要不要做「复制后自动弹出」？~~ 已决策 ✅**
**不做**，归入 §11 推迟清单。后续根据实际使用再评估（若要做，倾向「复制后托盘图标闪烁提示，点击才展开」而非直接弹窗）。

**Q3. ~~中→英翻译要不要给多个版本？~~ 已决策 ✅**
v1 只出一版译文，结果区下方放一个「换个说法」按钮，点击才重新生成。多版本并排、语域切换等留待实际使用后再评估。规格见 §3.5。

## 9. 审核流程

**每个里程碑结束时执行，不可跳过。**

1. **自检报告**。执行者输出该里程碑门禁表的逐条结果，格式为：`编号 | 通过/未通过 | 实测数据或截图路径`。性能类必须给实测数字，不接受估计值。
2. **未通过即停**。任一条未通过，停在当前里程碑修复，不得进入下一阶段，也不得以「后面一起改」为由推迟。
3. **人工审核**。由我逐条核对三件事：
   - 门禁是否真实通过（抽查 2–3 条自行复现）
   - 有没有偷加功能（对照 §10 推迟清单）
   - 有没有违反 §11 约束条款
4. **冻结**。审核通过后在本文档对应里程碑标记 `✅ 冻结 @日期`。
5. **变更走记录**。冻结后如需返工，在文档末尾追加变更记录（原因 / 改动 / 影响范围），不直接改正文。

## 10. 约束条款（给执行者）

违反以下任一条，该里程碑直接判未通过。

1. **不得引入 §1 依赖清单之外的第三方库**。确有需要时停下来说明理由并等待批准。
2. **不得在 M0 阶段做 UI 样式**。先跑通状态机与延迟指标，样式留到 M4。
3. **不得「统一」§3.3 的流式不一致**。查词非流式、翻译流式是刻意设计。
4. **不得实现 §11 推迟清单中的任何内容**，包括「顺手加一下」。
5. **不得修改 §4.1 的 IPC 命名**。
6. **遇到本文档未规定的设计决策，停下来问，不要自行发挥**。宁可多问一次，不要事后返工。
7. **不得为了通过门禁而放宽门禁**。指标达不到就报告达不到，附上实测数据和原因分析。

## 11. 明确推迟（v2+）

OCR、macOS 版、Apple 翻译框架降级、划词自动触发（辅助功能权限）、**复制后自动弹出**、**双击 Ctrl 等修饰键连击热键**（需低级键盘钩子）、译文多版本并排与语域切换、生词本 / Anki 导出、历史持久化、多引擎并排对比、插件系统、主题、自建中转与免费额度、移动端。

**日语等其他语言的专门优化**（活用还原、假名读音、敬语层级）也在这一列。v1 的通用路径能翻译日语，但不做词典级支持——等中英这条主线打磨好了再说。
